# 部署说明 — astrbot_plugin_pc_control v1.0.1

> 适用对象：把本插件拿到**另一台机器**的 AstrBot 上部署。
> 本机验证版本：**AstrBot 4.27.2**（内核 4.27.x）。更低/更高版本 API 可能略有差异，若报
> `ImportError: cannot import name ... from astrbot.core...` 请以你的内核版本为准调整 `main.py` 的 import。

本插件让模型在本机“看屏幕 + 动手操作”（截屏 / 鼠标 / 键盘 / 剪贴板 / 窗口 / 程序启停），
全部注册为 LLM 函数工具（`pc_*`）。

---

## 1. 放置路径

把解压出来的整个 **`astrbot_plugin_pc_control\`** 目录，放到目标 AstrBot 实例的插件目录：

```
<你的AstrBot实例目录>\core\data\plugins\astrbot_plugin_pc_control\
```

- `<你的AstrBot实例目录>` 指该实例自己的数据根目录（不同启动方式路径不同，**不要照抄别人的绝对路径**）。
  例如用 astrbot_launcher 时形如 `...\instances\<实例ID>\core\`，其下 `data\plugins\` 才是插件目录。
- 目录名必须正好是 `astrbot_plugin_pc_control`，它同时就是 AstrBot 识别用的 **插件 id**，
  必须与 `metadata.yaml` 里的 `name:` 一致；改名会导致加载/重载失败。
- 也可以走 **WebUI → 插件市场 → 本地安装** 选择这个 zip（或解压目录）安装。
- 放好后在 **WebUI → 插件** 里启用它（或在插件页点“重载”），**无需重启核心进程**即可生效。

> 解压后目录里应直接能看到 `main.py` / `pc_control.py` / `metadata.yaml` / `_conf_schema.json` /
> `requirements.txt` / `README.md` / `部署说明.md`，**不要再套一层同名子目录**。

## 2. 依赖装进哪个 Python（关键）

**必须装进该 AstrBot 实例自己的虚拟环境（venv），不是系统 Python。**
通用写法（Windows）：

```powershell
& "<你的AstrBot实例目录>\venv\Scripts\python.exe" -m pip install -r "<插件目录>\requirements.txt"
```

即：`<实例目录>\venv\Scripts\python.exe`。若你的部署不是标准布局，就找到运行 AstrBot 主进程的那个
python（`WebUI 关于页` 或启动日志里通常能看到解释器路径），用它来 pip 安装。

- 装错解释器的症状：`/pcstatus` 里依赖全部显示“缺失”，但你在系统 python 里 `pip list` 明明装了。
- 换国内源（可选）：

  ```powershell
  & "<实例目录>\venv\Scripts\python.exe" -m pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r "<插件目录>\requirements.txt"
  ```

- 安装后建议重载插件或重启一次核心，让新装的包在新进程里生效。

依赖清单与“缺了会怎样”见 `requirements.txt` / `README.md`。要点：
- **必需**：`Pillow`、`pyautogui`（缺了截屏 / 控制类直接不可用）；
- **强烈建议**：`mss`（整屏抓取）、`pyperclip`（剪贴板 / 中文输入）、`psutil`（结束进程）；
- **可选（会优雅降级）**：`pygetwindow`（缺了走内置 ctypes Win32 枚举）、`uiautomation`（缺了不读浏览器 URL）。

> 注意：本实现用 Python 标准库 `ctypes` 直接调 Win32，**不需要 `pywin32`**。

## 3. ⚠️ 头号坑：装好后还要在人格里放行 `pc_*`

**这是部署后“模型说我没有截屏工具”的第一大原因，插件本身没坏。**

AstrBot 的人格（persona）有一个「工具」白名单字段 `tools`，语义：

| `tools` 取值 | 含义 |
| --- | --- |
| **`[]`（空列表）** | **一个工具都不给** —— 模型看不到任何 `pc_*`，等于零工具 |
| **`null`（不设置 / 未配置）** | **全放行** —— 所有已注册工具都可用 |
| `["pc_screenshot", "pc_list_windows", ...]` | 只放行列表里列出的这些工具 |

操作：**WebUI → 人格 → 编辑当前人格 → 「工具」**，把需要的 `pc_*` 勾上/加进去；
或把该人格的 `tools` 留空 —— 但“留空”必须是 **`null`**，写成空数组 `[]` 反而会禁用全部工具。

自查：发 `/pcstatus`，只要看到「已注册工具 17 个」，说明**插件侧没问题**，问题就出在人格白名单 / 当前会话用的不是那个人格。

## 4. 配置项（WebUI → 插件 → astrbot_plugin_pc_control → 设置）

按 `_conf_schema.json` 逐条：

| 配置键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enable_control_tools` | bool | `true` | **总开关**。关闭后所有 `pc_*` 工具都不注册，等于停用插件功能（但仍可热加载）。 |
| `require_admin` | bool | `true` | 控制类工具（鼠标 / 键盘 / 剪贴板写入 / 启动或结束程序 / 切窗口）是否要求管理员。**强烈建议保持开启**；非管理员调用会被拒绝并提示如何加白名单。 |
| `require_admin_for_screenshot` | bool | `false` | 截屏 / 窗口列举 / 剪贴板读取是否也要求管理员。默认关闭（截图不改系统状态）；屏幕上有敏感信息时建议打开。 |
| `extra_admin_ids` | text | `""` | 额外允许的调用者 ID（逗号分隔），配合 `require_admin` 使用。例如 `123456789,webchat_user`。仅当事件的 `role` 不是 admin 时才需要填。 |
| `failsafe` | bool | `true` | pyautogui.FAILSAFE 救命开关。开启后鼠标被拖到屏幕**左上角**会立刻抛异常中断自动化，**务必保持开启**。 |
| `mouse_pause` | float | `0.05` | pyautogui 每次动作后的停顿（秒）。调大可降低误操作速度，给用户按 FAILSAFE 的时间。 |
| `screenshot_dir` | string | `""` | 截图保存目录。留空 = 系统临时目录下的 `astrbot_pc_control_shots`。 |
| `max_keep_screenshots` | int | `30` | 截屏目录最多保留的图片数量（原图 + 缩略图一起算），超过的旧图在下次截屏时自动清理。 |
| `screenshot_retention_days` | int | `0` | 截屏目录保留天数；`0` = **关闭按天数清理**（只按张数，默认保守值）。想自动清旧可设 `7`。 |
| `max_image_side` | int | `1280` | **进入模型上下文**的图片最长边（像素），`0` = 不缩放。发给用户的原图不受影响。 |
| `image_jpeg_quality` | int | `75` | 喂给模型的压缩图 JPEG 质量（1–95）。**只影响模型看到的清晰度**，不影响发给用户的图。 |
| `keep_recent_images` | int | `2` | 请求前只保留最近 N 张图片，更早的图片内容替换成一行占位文本；`0` = 图片一律不进上下文。 |
| `send_screenshot_to_user` | bool | `true` | 截屏后是否自动把图片（**原图**）发到当前会话。 |
| `type_text_by_clipboard` | bool | `true` | 含中文等非 ASCII 文本时用剪贴板 + Ctrl+V 输入。关闭后 `pc_type_text` 无法输入中文（pyautogui 打不出中文）。 |
| `restore_clipboard_after_type` | bool | `true` | 剪贴板输入文本后恢复原剪贴板内容。 |

## 4.5 v1.0.1 专项：图片体积治理 & 热重载修复（换机器部署必读）

### (1) 为什么会有 413

`pc_screenshot` 抓整屏 PNG（高分屏单张 3–4 MB），base64 后 ~4.6 MB 会被塞进
「工具结果 → 对话上下文」，**每次请求都重发**；历史不裁剪 → 请求体超过网关
（nginx `client_max_body_size`，默认 1 MB）→ **HTTP 413**。

### (2) 三层治理（都在本插件内，无需改网关）

1. **抓屏落盘时**顺手写缩略图 `<名字>-thumb.jpg`（`max_image_side` / `image_jpeg_quality`）；
2. **进模型上下文的一律是压缩版**：`encode_image_for_llm()` 优先复用缩略图，1280×720 JPEG q75
   的 base64 约为原图的 **9%**；
3. **请求前瘦身**：`@filter.on_llm_request` 钩子只保留最近 `keep_recent_images` 张图，
   更早的图片块替换为一行 `[图片已清理] …` 占位文本（文本 / `tool_calls` / `think` 一律不动）。

> **发给用户的是原图，给模型的是压缩版**：
> `send_to_user` 走 `MessageChain().file_image(原 PNG 路径)`（原图、尺寸如你所愿）；
> 只有喂给模型的 `ImageContent` 是压缩版。工具返回的 JSON 里会写明两份的
> 尺寸/体积/`source`，方便核对。
> **安全阀**：压缩结果若反而更大（小尺寸/纯色截图常见），就用原图那份
> （`source` 带 `+原图更小`），保证「进模型的那份永远不比原图大」。

实测（本机 1920×1080 噪声桌面图）：原图 2.15 MB → 缩略图/喂模型 1280×720 0.15 MB，
base64 203,660 字符（≈0.19 MB，**9.0%**）。

### (3) 截图目录清理（源头治理，默认保守）

`max_keep_screenshots`（默认 30 张）在**每次截屏后**自动清理超出的旧图，
并顺带删掉对应的 `-thumb.jpg`；`screenshot_retention_days`（默认 `0` = 关闭）
可按天数清理。想彻底不涨，把 `max_keep_screenshots` 调到 10–20 就行。

### (4) hot reload 实例引用 bug 已修

旧版 `terminate()` 无条件清空模块级插件引用；热重载时「新建实例 / terminate 旧实例」
顺序不保证，导致重载后所有工具报 **「插件实例未初始化」**。现在：

- `terminate()` 只在 `_PLUGIN is self` 时清空（若已指向新实例，**绝不动**）；
- 存活实例登记表 `_INSTANCES` 兜底（`_PLUGIN` 为空时取最新存活实例）；
- 已 terminate 的实例从登记表摘除。

**验收方式**：连续热重载 2 次 → 每次调
`GET /api/v1/plugins/extensions/astrbot_plugin_pc_control/selfcheck`，
看 `module_ref_alive=true`、`instances_alive=1`，且 `tool_path.ok=true`
（它会真的调一次 `pc_mouse_position` 的 `call()`，无副作用）——本机实测两次都 OK。

### (5) 历史里已有的大图怎么排查（只读，不要乱删）

见 `README.md` 第 8 节：用 `sqlite3` 只读打开 `core\data\data_v4.db`，
统计 `conversations.content` / `platform_message_history.content` 的
`data:image`、`iVBORw0KGgo`、`/9j/` 命中行数和体积。**先看现状再决定**，
要清优先用 WebUI 新建/清空会话；直接改库务必先备份且只针对具体 `conversation_id`。

## 5. 自检

在**任意会话**里给机器人发命令（需管理员，除非你把 `require_admin` 关了）：

- `/pcstatus` — 打印各依赖可用状态、屏幕分辨率、已注册工具清单，以及总开关 / 管理员 / FAILSAFE 当前值。
- `/pcdiag` — 在**插件进程内**做一次无害自检：截屏、光标坐标、剪贴板往返读写、窗口列表数量。
- `/pcdiag input` — 在上述基础上额外做一次鼠标移动往返（移到屏幕角落附近再还原），用来验证输入桌面是否可交互。

**还有两个不用进对话的 HTTP 自检接口**（Dashboard JWT 鉴权，GET；`<base>` 见上一节）：

- `GET <base>/api/v1/plugins/extensions/astrbot_plugin_pc_control/selfcheck`
  —— 只读：实例引用 / controller / 工具路径探针 / 图片策略 / 截图目录现状；
- `GET <base>/api/v1/plugins/extensions/astrbot_plugin_pc_control/capture_probe?capture=1`
  —— 抓 1 张图并报「原图 vs 缩略图 vs 喂模型的压缩版」的真实尺寸与体积；
  **不发消息、不进上下文**（不带 `capture=1` 则直接跳过）。

**排查要点（很重要）**：同一个插件代码，在**插件进程内**（模型真正调用时的上下文）和**外部脚本 / 子进程**
里看到的 Windows 会话可能完全不同。常见现象：

- 外部脚本测出来 `input_desktop unavailable`、截屏全黑、鼠标不动；
- 但在插件进程内（`/pcdiag`）一切正常。

**结论：以 `/pcdiag`（插件进程内）的结果为准**；外部脚本显示 `input_desktop unavailable` 通常是
“远程桌面会话断开 / 未登录交互桌面 / 子进程落在别的窗口站”，不代表插件坏了。

## 6. 已知限制（能力边界，先读再用）

- **尚未实测**：点击 (`pc_mouse_click`)、打字 (`pc_type_text`)、拖拽 (`pc_mouse_drag`)、滚轮
  (`pc_mouse_scroll`)、启动/结束程序 (`pc_launch_program` / `pc_kill_process`) 这一批“动手”功能，
  在本机验证时**未逐条实测**（验证以截屏 / 光标 / 剪贴板 / 窗口列举为主）。首次使用请在人看着的情况下小心试。
- **点击等无用输入桌面的情况**：若当前会话没有可交互输入桌面，光标移动会被系统静默拒绝，
  工具会返回带 `warning` 的“空操作”提示（而非报错），请以该提示为准。
- **浏览器地址栏 URL 读取“尽力而为”**：`pc_active_window` 用 `uiautomation` 尝试读浏览器地址栏，
  **读不到就只返回窗口标题，不硬凑、不报错**（需要 `uiautomation` 且能连到同一桌面）。
- **pyautogui FAILSAFE**：默认开启。若当前光标本来就在屏幕 **`(0,0)` 左上角**，任何鼠标动作都会
  抛 `FailSafeException` —— 这**是正常设计**（救命开关），不是 bug。人工把鼠标移离角落即可；
  或在配置里临时关 `failsafe`（不推荐）。
- **结束进程**：必须显式传 `confirm="KILL"`；内置系统关键进程黑名单，防止误杀。
- **单窗口截图**依赖窗口能做 `PrintWindow`；个别 UWP/受保护窗口可能截到空白或失败（会跳过并报明细）。
- 本插件**只在 Windows 上有意义**（大量 Win32 调用）。

## 7. 兼容性

- 本机验证：**AstrBot 4.27.2**（内核 4.27.x）。
- 目标机器同样的平台：**Windows**。
- 插件 id：`astrbot_plugin_pc_control`（= `metadata.yaml` 的 `name`，也是目录名）。
- 版本：**v1.0.1**（v1.0.1 新增：图片体积治理、hot reload 实例引用修复、四个新配置项、两个自检路由）。

### v1.0.1 已知限制（不影响可用性）

- 抓屏时产出的 `-thumb.jpg` 只在「确实比原图小」时才落盘。低分辨率桌面（如 1024×768）
  或纯色画面下 PNG 本身只有几十 KB，JPEG 反而更大 → 不产缩略图，喂模型的那份退回原图
  （`source` 会写 `reencoded+原图更小`）。这是有意为之的安全阀，不是故障。
- `max_image_side` / `image_jpeg_quality` 只作用于**进模型上下文**的那份；
  发给用户的原图永远是抓屏原始分辨率，想改只能改屏幕分辨率或另做后处理。
- 历史里**已经存在**的大图 base64 不会被自动清掉（插件只影响新请求内容）；
  清理办法见 `README.md` 第 8 节，建议在 WebUI 里新建/清空会话。
- `screenshot_retention_days` 默认 `0`（关闭）。若你手动改成非 0，请确认截图目录里
  没有你需要长期保留的图。
